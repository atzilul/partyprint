# PartyPrint — הפעלת התראות הזמנה

הקוד משתמש ב־Resend דרך HTTPS. אין צורך בתוסף SMTP או בתלות חדשה.

## מה נשלח ולמי
- אחרי שמירת ההזמנה: מייל בעברית וביישור לימין לבעל האתר ולחברי הצוות בתפקיד manager. תפקיד חסר מטופל כמנהל, בהתאם למנגנון ההרשאות הקיים.
- כתובת הבעלים היא PARTYPRINT_ADMIN_EMAIL, עם ברירת המחדל הקיימת במערכת. כתובות כפולות מוסרות.
- מעצבים ובית הדפוס אינם נמענים. כל המנהלים רואים את רשימת הנמענים.
- התבנית כוללת את לוגו האתר, פרטי הלקוח, חבילה, כמות, סכום הבקשה, בריף, מידות וצבעים וקישורים לניהול, לוואטסאפ ול־ZIP.
- פרטי ההזמנה נשלחים ל־Resend לצורך השליחה. הערות פנימיות אינן נכללות בתבנית.
- קישור ZIP תקף כברירת מחדל ל־7 ימים, לפי PARTYPRINT_BUNDLE_LINK_DAYS. כל מי שמחזיק בקישור יכול להוריד את הקבצים.
- כשל בספק אינו מבטל הזמנה שכבר נשמרה. נשמר הסטטוס הקיים, וניתן לנסות שוב ממסך ההזמנה.
- לא נוספה שליחה אוטומטית חוזרת ברקע. פעולת השליחה מחדש הקיימת מוגבלת לפעם בדקה לכל הזמנה.
- אישור של ספק המייל אינו אישור שההודעה הגיעה לתיבה. יש לבדוק מסירה בחשבון Resend.

## חיבור בחשבון Resend
1. היכנסו לחשבון שלכם ב־https://resend.com/domains והוסיפו את partyprint.co.il או תת־דומיין ייעודי לשליחה.
2. העתיקו למערכת ה־DNS את הרשומות המדויקות ש־Resend מציג עבור SPF ו־DKIM. אל תחליפו רשומות MX קיימות של תיבת הדואר הראשית. השתמשו בשם הרשומה שמציג הספק.
3. המתינו למצב Verified של הדומיין.
4. צרו מפתח API לשליחה בלבד, מוגבל לדומיין המאומת.
5. בהגדרות משתני הסביבה של אפליקציית Node ב־Hostinger הגדירו:
   - RESEND_API_KEY: המפתח הסודי, ישירות בממשק השרת.
   - MAIL_FROM: לדוגמה PARTYPRINT <orders@partyprint.co.il>, רק כאשר הדומיין הזה מאומת בחשבון.
   - PARTYPRINT_PUBLIC_URL: https://partyprint.co.il
   - PARTYPRINT_ADMIN_EMAIL: כתובת בעל האתר שמקבל את ההתראות.
6. פרסו את הקוד והפעילו מחדש את האפליקציה כדי שהמשתנים ייטענו.

אין להכניס את המפתח לקוד, ל־GitHub, למשתנה NEXT_PUBLIC או לשיחה. אימות דומיין ושמירת המפתח לא בוצעו כחלק משינוי הקוד הזה.

## בדיקת ההפעלה
1. במסך הגדרות הניהול מופיעים מצב ההגדרות ורשימת הנמענים. החיווי בודק נוכחות משתנים בלבד, ואינו בדיקת אימות מול הספק.
2. השתמשו בהזמנת בדיקה עם פרטים שאתם מורשים לשלוח, ושלחו את ההתראה מחדש מתוך ההזמנה.
3. בדקו ב־Resend שהשליחה התקבלה ונמסרה, ובתיבה את יישור העברית והלוגו. בדקו גם ספאם.
4. בדקו שכפתור הניהול פותח את ההזמנה אחרי התחברות, שוואטסאפ פונה למספר הנכון ושה־ZIP יורד.
5. בדקו גם במכשיר נייד. רינדור של Outlook ולקוחות מייל אחרים עשוי להשתנות; הטבלאות והעיצוב המוטמע נועדו לתאימות רחבה.

## בדיקות פיתוח
הריצו node scripts/verify-order-mail.mjs לבדיקות הנמענים, escaping וקישורים.
נדרש להשלים typecheck/build ובדיקת דפדפן כשסביבת הפיתוח זמינה. בעת הכנת השינוי סביבת העבודה נותקה; לא בוצעה שליחה חיה.
