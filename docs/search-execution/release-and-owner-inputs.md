בדיקת תוכן שהתקבל בכלי קריאה אינה בדיקת לחיצות ומילוי טופס. חובה לציין כל בדיקת אינטראקציה שלא התאפשרה.
הבדיקה הציבורית מתמקדת בנתיבים ציבוריים. אין לסרוק כתובות מעקב או עיצוב של לקוחות אמיתיים.

כלי האימות הקיימים בענף:
- node --test scripts/search-utils.test.mjs
- npm run build
- node scripts/check-search-build.mjs
- npm run seo:check
- npm run seo:indexnow (dry-run)

ה-job של production-audit מסומן continue-on-error כדי להציג ממצאים על הגרסה החיה בלי לפסול מועמד שעדיין לא פורסם. לכן סימון workflow כללי ירוק אינו מחליף קריאת דוח production-audit.
בסשן קודם נבדקו 59 עמודי HTML קיימים עם 200. נמצאו שכפול סימון דף הבית ותגובות 200 לכתובות חסרות; אלה דפוסי בעיה, לא הוכחה ל״עשרות עונשי Google״ ולא מדד אינדוקס.

## בדיקת שליחה מלאה
שליחת /api/orders שומרת פנייה ומנסה לשלוח התראות. זו אינה בקשת GET לצורכי SEO.
לפני שליחה חיה יש להגדיר מסלול בדיקה מפורש: מטרה, פרטי בדיקה מורשים, האם התראות יישלחו, נמען מאושר, סימון ותהליך טיפול ברשומת הבדיקה.
אין ליצור הזמנת דמה או לשלוח הודעת בדיקה ללקוח מתוך בדיקת SEO כללית.
בדיקת הקצה מתעדת בקשה אחת, תשובת שמירה, מספר פנייה במערכת המורשית ומצב התראה. ״accepted״ בשירות מייל אינו הוכחת הגעה לתיבת הנמען.
מצב Resend ו-MAIL_FROM נבדק במערכת המתאימה אם נדרש; לא מכנים אותו מאומת לפי קיום משתני סביבה.

## שער 4 — הודעה למנועי החיפוש
אחרי אימות העמודים והפריסה:
1. Google Search Console: לאתר נכס קיים, לשמר אימות, לבדוק קריאת sitemap ולבצע URL Inspection לדפים המועדפים.
2. Bing Webmaster Tools: לאתר נכס קיים, לאמת את הדומיין ולהגיש מפה.
3. IndexNow: dry-run, בדיקת כתובות ואז npm run seo:indexnow -- --submit. שמירת תגובה ותאריך; אין הגשה יומית ללא שינויים.
4. מעקב קליטה לפי דוחות המנועים; זמן הקליטה אינו מובטח.
5. אין שימוש ב-Google Indexing API רגיל כאמצעי גורף להגשת דפי חנות.

## שער 5 — עותק preview
רק לאחר אימות Hostinger מסנכרנים את הפרויקט הקיים ב-Sites. אין יצירת אתר חדש.
לוודא אם העותק מוגבל בגישה או מציג noindex במידע הציבורי. עותק שכבר מופיע בחיפוש דורש בדיקה נפרדת; אין הבטחת הסרה מיידית.
אם מקור/קבלה חסרים, יש תיעוד מפורש של מצב העותק והייצור; לא קוראים ל-preview ״האתר המעודכן״.

## עצירה ושחזור
כשל טופס שמירה, שגיאת שרת רחבה או חשיפת נתונים עוצרים הרחבת תוכן.
בודקים תחילה דיפרנציאל קוד והגדרות פריסה. חזרה לגרסה יציבה נעשית עם גרסה ידועה ולפי הרשאות; אין למחוק נתונים, להחליף מסד או לדרוס העלאות לקוחות.
שומרים את זמן האירוע, הקומיטים והראיות ומוודאים שהשחזור פעל.
תקלה בנתוני מדידה בלבד מסומנת בנפרד; אין לטעון שירידת סשנים היא בהכרח ירידת ביקוש.
